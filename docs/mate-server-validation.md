## クライアント互換性

比較元は公開サーバーと同じ`9cef7334`のcontracts/remote実装。旧ScoreJsonにはtype/valueのみがあり、JSONの未知フィールドを無視し、type=mateは無条件にScore.Mateへ変換する。

- 確認済みmateの`verified: true`が追加されても、旧クライアントのデコードは失敗しない。
- 未確認mateの`{type: "mate", value: 17}`は、旧クライアントには17手詰になる。新クライアントは未確認の17手勝ちとして扱う。
- cpのJSONは従来と同じ。

通信互換はあるが、新しい表示上の区別は旧アプリには伝わらない。実際の旧版サーバーも同じ実戦局面で未確認mate=13を返しており、旧アプリの「13手詰」は今回初めて発生する退行ではない。サーバー更新だけでは既存の誤認を解消できず、区別を適用するには新アプリへの更新が必要。旧アプリでも未確認mateを詰みと表示させないことを公開条件にする場合は、未確認mateを数値で返すなどの版別返却が別途必要。

再現テストは`LegacyMateCompatibilityTest`。旧版のDTOと変換規則をテスト内に再現し、新版DTOとのデコード結果を比較する。旧アプリの実機画面を操作した試験ではない。
