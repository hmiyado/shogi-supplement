# 詰みの統計

「推定棋力」の対局ごとの推移と対局サービスの間に、見出し「詰み」の棒グラフを置く。横軸は詰み手数、縦軸は成功率。凡例、選択状態、内訳パネル、操作説明は置かない。集計の表示案は[モック](mockups/mate-statistics.html)にある。

## 集計単位

自分の手番で、確認済みの詰みがある局面から始まる一連の機会を数える。着手前に記録された最初の詰み手数を使い、途中の着手数や、その後に変わった詰み手数では重複計上しない。実際の着手がない最後の局面では新しい機会を作らない。

- 9手詰が発生し、解析上の詰みが消えた。その後5手詰が発生して投了まで続いた場合は、9手詰の見逃し1件、5手詰の成功1件。
- 5手詰が発生し、手順が延びて11手詰になっても、詰みが消えず投了まで続いた場合は、5手詰の成功1件。
- 5手詰が確認され、その後エンジンが未確認の3手勝ちを報告した場合は、5手詰の見逃し1件。報告された符号・手数は問わない。その後に確認済みの詰みが現れ、ユーザーが着手すれば新しい機会として数える。
- 詰みがある途中の3手詰・1手詰などを別の発見として数えない。

機会の成功は、最後まで詰みが確認され、本人の勝ちで相手の投了または詰みにより終了した場合だけ数える。切れ負け、引き分け、勝者不明、終局理由不明では成功を推測しない。途中で反対側の確認済み詰みに変わる場合や、未確認mateに変わった場合も、その機会を失ったものとして扱う。

## 解析結果と不確実性

保存済みposition_evalの確認済みmateを使用する。先手視点の符号を本人視点に戻す。mate 0はその局面の手番側が詰まされたことを表す。確認済みの機会が始まった後、mateInが非nullの未確認mateに変わった時点を、確認済み詰みが検出されなくなった境界として見逃しに数える。これはエンジンが報告したmateであり、確認済み詰みではない。報告された符号・手数、手番、その後の勝敗、再登場する確認済み詰みにかかわらず、その機会は終了する。未確認mateから新しい機会は始めない。

通常評価値（cp）へ変わった時点も同じ境界として見逃しに数える。これらは詰みが数学的に存在しない証明ではない。統計はその解析条件が確認した詰みに基づき、指した本人の認知や、探索が見つけなかった詰みの総数を直接測るものではない。

一方、局面評価の欠落、重複、値がない行は判定不能とする。その区間を通る機会は、後で詰みや勝ちが確認できても成功・見逃しの割合から除外する。

成功率は成功数 /（成功数 + 見逃し数）。判定不能だけの手数、詰み機会がない手数は割合を出さず「—」。分母は棒の下に併記する。旧解析の未確認mateを確認済みとみなさない。再解析で保存済みの結果が更新されれば集計も変わる。

## 範囲と保存

ホームと同じ解析済み・本人の側が分かる棋譜集合を使う。推移グラフの直近30日制限とは独立し、詰みは保存されている全対象棋譜を集計する。確認状態を読み直すため、集計専用の永続キャッシュや新しいDB列は追加しない。データ削除や再解析後の再読込で元データに追従する。集計は共通ViewModelのIO dispatcherで行い、AndroidとiOSで同じロジックを使う。

横軸の終端は実際に発生した機会の最大手数とし、31手以上は31+に合算する。手数ごとの割合を平均せず、成功数・見逃し数を合算してから割合を求める。手数が多い場合は横スクロールし、縦軸を固定する。機会がなくてもグラフ領域の高さを保つ。

## 今回の範囲

全体の「詰みの継続」指標は追加しない。詰めろ対応率は今回の集計に含めない。先に各局面で詰めろの判定と根拠手順を確認できる機能を別途検討する。通常評価の負mateや大きな劣勢を、そのまま詰めろと見なさない。

## 検証

集計では上記3例、手数が短くなる途中の重複除外、後手の逆符号と再登場、未確認mateへの遷移と未確認mateから開始しないこと、未確認mateより優先される欠落・重複・null、投了以外の終局、31手以上の加重集約と欠測を確認する。UIでは320dpの100%・0%・欠測・31+までの横スクロール・空データ・暗色を撮影して確認する。
