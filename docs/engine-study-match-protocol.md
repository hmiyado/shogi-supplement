# 検討専用エンジンの同一実時間比較

2026-09-27、結果を見る前に固定した予備検証条件。対象はサーバー検討専用の候補であり、通常解析・棋力推定の置換ではない。

- 比較: 9.40＋Háo（基準）対9.80＋Aoba（候補）。版・評価関数・バイナリは前回[固定ノード比較](engine-profile-validation.md)と同じ。
- 開始局面: #102の既存候補がある対局のうち24手以上の履歴がある対局を対象に、`SHA256('study-match-v1:' + game_id)`順で32対局。各対局の24手目までを使用し、候補の悪手局面自体からは開始しない。先後交換の計64局。過去の7棋譜28局対局とは別の選定。
- 1手200ms、Threads 1、Hash 128MB、MultiPV 1、定跡無効、通信遅延・最低思考時間0。FV_SCALEはHáo 20、Aoba 40。各対局前にreadyok待ちとusinewgame。全履歴をエンジンへ渡す。
- 同時探索なし。対局ごとに先後を交換し、ペアごとに先に実行する先後も交代。計測中は別の重い処理を開始しない。
- 終了: 詰み・投了・合法手なし・千日手・連続王手千日手。連続王手は同一局面4回の区間における全着手を検査。開始局面後320手で打ち切り。入玉宣言・判定不能の反復は独立確認待ちにし、勝ちとして扱わない。
- 全着手の合法性、思考時間、USI出力を保存。エンジン異常や違法手では計測を失敗とし、都合のよい対局だけを除外しない。途中結果による打ち切りや標本追加はしない。
- 候補の得点率は勝1・引分0.5・負0。推定単位は先後ペアとし、32ペアの平均得点率に対してseed=101、20,000回のペアbootstrapで95% percentile区間を算出。打ち切り・未判定は別集計し、採用の肯定根拠に使わない。ペア間のプレイヤー重複等による依存は残る。
- 下限が50%を超えれば、この標本・短時間条件で候補優位を支持する予備証拠とする。50%を含めば改善未実証。どちらもLinux本番性能や長時間の検討品質の証明ではない。
- MultiPV 1の対局性能と、複数候補を表示する検討UIの品質は別。正式採用にはnative Linuxでの実時間・メモリ・費用、実際の検討条件の結果、保存・互換性・rollbackの確認を残す。棋力推定の再較正や端末への候補エンジン同梱は、この採用範囲では条件にしない。

再現コマンド（リポジトリルート。入力・評価関数・バイナリはローカル作業資産）:

```sh
python3 tools/match_engine_profiles.py \
  --profiles /path/to/study-match/profiles.json \
  --openings /path/to/study-match/openings.json \
  --output /path/to/study-match/games --milliseconds 200
```

## 対局開始後の補足（主解析は変更しない）

320手打ち切りが発生したため、完全判定を前提とする主解析に加え、未判定をすべて候補の負け／すべて候補の勝ちと置いた得点率の範囲と、それぞれのペアbootstrap区間を補助集計する。未判定局を除外せず、引き分けにも変換しない。この感度分析は打ち切りを見た後に追加したもので、事前定義の主解析と区別する。

対局後、同じ32開始局面で1局面1秒・MultiPV 3の逐次プローブも行う。目的は全候補の合法性、複数候補の出力、時間条件の確認であり、検討の正解率を測る試験ではない。各局面で初期化して履歴を渡し、2構成の順序を交代させる。
