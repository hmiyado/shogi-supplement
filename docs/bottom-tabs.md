# 下タブの画面構成（#106）

対象はAndroid/iOS。Webは対象外。操作モックは[bottom-tabs.html](mockups/bottom-tabs.html)。

- ホーム・棋譜・定跡をルートタブとする。ホーム内の一覧リンクを置き換える。
- Androidではホーム・棋譜タブに「棋譜を追加する」を表示する。iOSでは右下の独立した「＋」から棋譜を追加する。定跡タブには「定跡を追加する」を表示する。
- 一覧のスクロール位置・適用済み絞り込みはタブ往復で保持する。
- レポート・定跡編集・次の一手問題・設定・追加画面はタブを隠す。戻り先は起点タブとする。設定内の子画面は設定へ戻す。
- 編集画面はタブ切替できない。保存して戻るか、未保存の破棄確認後に戻る。
- 解析中から一覧に戻っても解析を継続する。解析画面を閲覧中の完了はレポートへ、別タブ閲覧中の完了は完了表示のみ。要求ID照合を維持する。
- Androidの戻るは詳細を閉じる、ルートの棋譜/定跡ではホーム、ホームではOS既定動作。タブ再選択は位置をリセットしない。

iOSはOS標準のLiquid Glassを利用する。

共通のRootNavigationがタブ選択・戻り先・完了通知を保持する。RootTabShellが表示の切替・SaveableStateHolderによる一覧状態保持を担当し、OS固有部品へ選択と操作コールバックだけを渡す。iOSでは本文をセーフエリアまで描画し、下タブを重ねる。一覧の下余白はcontentPaddingで確保し、スクロール中の内容はタブ背後まで表示する。定跡の追加ボタンはタブより上に配置する。iOSのPlatformRootTabBarはUITabBarControllerを使用し、ガラス素材を独自描画しない。AndroidはMaterialのNavigationBar。iOS 26以降はLiquid Glass、それ以前はOS標準の外観になる。

NavigationMachineのSelectTabとReturnToTabを遷移図へ反映する。Androidの遅延一覧ロードは起点画面と選択タブを照合し、タブ切替後の結果では現在地を変えない。

検証: 共通ナビゲーションの戻り先・完了通知、一覧のフィルタ保持、定跡編集時のタブ非表示/復帰を自動テストで確認。iOS 26.5シミュレータでネイティブタブの切替と表示を確認。iOS実機へのインストール・起動まで確認し、実機での画面操作は未確認。

ホームの追加ボタンには背景の面を敷かない。iOS棋譜一覧は同期・局面ラベル照合が完了するまで読み込み表示とし、ラベルなしの一覧を先に表示しない。

ホーム/棋譜の横長追加ボタンを、3ルート共通の右下の独立した「＋」へ置き換える。検索タブを流用せずUIButtonのglass設定を使う。タイトルは背景面なし、設定は丸いガラスボタン。Androidは既存の追加ボタンとヘッダーを維持する。iOS 26未満のアクションは標準tintedボタンへフォールバック。

定跡一覧のタイトルは「定跡一覧」。手動同期ボタンは廃止し、棋譜一覧と同様の選択削除ボタンを配置する。削除確認後は文書のdeletedフラグを保存・同期し、一覧から除外する。局面ラベルは削除しない。旧バージョンはdeletedフラグを解釈しないため、旧クライアントでは削除済み定跡が表示される互換性上の制限がある。
